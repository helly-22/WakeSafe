# Sanity checks

How to verify WakeSafe locally, and what the last run found.

Last run: 2026-10-24 on `helly/api-demo-menopause` at `804d317` (same files as `origin/main`
at `202e244`), Windows, Python 3.11.9, Node 24.19.0.

## How to run

Python dependencies come from `requirements.txt` (repo root). Run each suite from the
folder shown; there is no shared `conftest.py` or `pytest.ini` yet.

| Check | Folder | Command |
| --- | --- | --- |
| Backend tests | `backend/` | `python -m pytest -q` |
| ML + script tests | repo root | `python -m pytest ml/tests scripts/tests -q` |
| Synthetic data tests | `synthetic_data/` | `python -m pytest -q` |
| Frontend install | `frontend/` | `npm ci` |
| Frontend typecheck + build | `frontend/` | `npm run build` |
| Backend server | `backend/` | `python -m uvicorn app.main:app --port 8000` (docs at `/docs`) |
| Frontend dev server | `frontend/` | `npm run dev` (http://localhost:5173) |

Run the backend tests from `backend/`. From the repo root,
`services/explanations/tests/test_explain.py` fails to import `app`.

### End-to-end pipeline

A one-off script (not committed) ran all 66 synthetic personas through
`load_nights -> compute_features -> score_apnea -> assess_risks -> recommend_care -> explain`,
the CSV upload path, the live-WHOOP stub, and every API route.

Passed:

- Every step returns valid contract models.
- Missing SpO2 stays `None`, never 0. Synthetic data is flagged; CSV uploads are not.
- No apnea probability is exposed. No diagnostic wording in explanations or factors.
- Red flags always set `urgent_override`, care tier `Urgent` and 911 guidance. `Urgent`
  never appears without the override. No capacity is labeled `live`.
- Live WHOOP raises `NotImplementedError` without credentials.
- API: `/`, `/health`, `/docs` and all six `/demo/{persona}` return 200. An unknown persona
  returns 404 and malformed bodies return 422.
- Care ranking now uses the real `hospitals.csv`: every recommendation has a drive time and
  a specialty match, and results change with location (Boston, Worcester, Springfield).

## Known issues

1. **Demo fixtures are not committed.** `scripts/fixtures/*.json` (7 files, generated by
   `scripts/gen_synthetic.py`) exist only on one machine. On a fresh clone, `/demo/*`
   returns 500 and 4 tests in `tests/test_api_smoke.py` fail with `FileNotFoundError`.
2. **Four of six demo personas never reach the trend rules.** `compute_features` needs at
   least 14 nights (7 recent + 7 earlier) for baseline z-scores. NORMAL (7), CARDIO (10),
   ALTITUDE (5) and JETLAG (5) have fewer, so all their z-scores are `None`. CARDIO flags
   nothing cardiovascular, and ALTITUDE/JETLAG show nothing about travel.
3. **Travel context is dropped.** The fixtures carry `travel_context`, but
   `api/demo.py` ignores it and no `travel:*` flag reaches `FeatureSet.data_quality_flags`,
   so the risk engine's travel relaxation never runs in the demo.
4. **Frontend and backend routes don't match.** The frontend calls `GET /api/demo/personas`
   and `POST /api/screening/analyze` (both 404). The backend serves `/demo/{persona}`,
   `/screen`, `/care`, `/explain`, `/report`. Response shapes also differ (`AnalyzeResponse`
   vs `DemoResponse`), so the frontend still runs only on its built-in mock data.
5. **Care ranking barely depends on risk.** 19 of 20 hospitals list `med_surg`, which the
   matcher maps to pulmonology, sleep medicine and primary care, so specialty fit is nearly
   identical everywhere. Within one location, NORMAL and APNEA get the same top facilities;
   only the care tier differs.
6. **Capacity is never used.** `matcher.py` imports `get_capacity_score`, which `capacity.py`
   does not define, so every recommendation has `capacity_source="unknown"`.
7. **Demo personas have an empty intake profile.** `api/demo.py` uses `ProfileInput()`, so
   STOP-Bang is 0 and apnea tiers come from wearable trends alone.
8. **Signatures differ from `TEAM_CONTRACTS.md` §4.2** (`recommend_care`, `explain`), and
   `services/reports` (PDF) and live WHOOP OAuth are not built. `requirements.txt` lists no
   `fastapi`/`uvicorn`/`httpx` and pins no versions.
9. **Three frontend screens are placeholders:** Health Intake (read-only), Find Care and
   My Report.

# Core-idea sanity checks (the pitch: image flow + travel + clinician note)

These are not "does it run" — they are "does WakeSafe actually do the thing we
demo". Each is a yes/no a non-coder can check, with how to check it and its
status from the 2026-10-24 run. The flow being tested, left to right:

    flags (apnea / menopause / other) -> risk aggregator -> app ->
        clinician note (numbers/graph/frequency) + care routing (beds/specialty/wait)
    ...with travel adjusting the baseline so trips don''t false-alarm.

## A. The flow (the image)

- [ ] **A1. A flag actually fires.** `GET /demo/APNEA` -> Sleep-disordered breathing = Moderate/High (not Low). STATUS: PASS.
- [ ] **A2. Menopause is a real flag.** `GET /demo/MENOPAUSE` -> Menopause/perimenopause = Moderate/High. STATUS: PASS.
- [ ] **A3. The aggregator returns all risk groups together**, each with its own tier, in one RiskAssessment. STATUS: PASS (6 groups).
- [ ] **A4. Flag -> care routing is connected.** A fired flag produces care recommendations in the same `/demo` call. STATUS: PASS.
- [ ] **A5. Different person -> different result.** NORMAL persona does NOT flag the same as APNEA. STATUS: PARTIAL — NORMAL has too few nights (7) to reach the trend rules, so it under-flags rather than cleanly reading "all clear". (known issue 2)

## B. Clinician note (the differentiator)

- [ ] **B1. Every flag shows WHY with real numbers**, not just a tier — e.g. "SpO2 min 86; below 90% on 4 of 7 nights". Check `explanation.risk_explanations`. STATUS: PASS.
- [ ] **B2. Evidence is machine-readable for a graph** — each explanation carries an `[EVIDENCE]{json}` block with a dated series + headline numbers. STATUS: PASS.
- [ ] **B3. Prose is short** — a few lines max after the evidence, not a wall. STATUS: PASS.
- [ ] **B4. No diagnosis language** — never "you have X"; screening words only; the numeric risk score is never shown as a verdict. STATUS: PASS.
- [ ] **B5. Honest limitations present** — screening-not-diagnosis, derived-WHOOP-metrics, few-nights. STATUS: PASS.
- [ ] **B6. Urgent -> 911.** A red-flag symptom forces Urgent + "call 911", bypassing routine care. STATUS: PASS.

## C. Travel (the smart part: suppress false alarms)

- [ ] **C1. An altitude night does NOT false-alarm.** A low-SpO2 night tagged `travel:altitude:*` should be relaxed, with the note "fits the altitude you''re at; watching for persistence at home". STATUS: **FAIL in the demo** — the rule works in unit tests, but `api/demo.py` drops `travel_context`, so no `travel:*` flag reaches the engine on the demo path. (known issue 3)
- [ ] **C2. Care routes to where you ARE, not home.** Same risk, different lat/lon -> facilities near the current location. STATUS: PASS (results change Boston/Worcester/Springfield).
- [ ] **C3. The clinician note travels** — the one-page `/report` is self-contained and sh\
 owable to a clinician elsewhere. STATUS: PASS (report assembles); PDF export NOT built (known issue 8).
- [ ] **C4. Trip-aware check-in captures context** (traveling? alcohol? sleep?). STATUS: NOT BUILT as an endpoint.

## D. Honesty / safety (judges will probe these)

- [ ] **D1. Simulated is never shown as live** capacity. STATUS: PASS (but capacity is unused — known issue 6).
- [ ] **D2. Synthetic data is labeled** synthetic, never presented as real patient data. STATUS: PASS.
- [ ] **D3. Missing SpO2 is `None`, never 0** (no fake-healthy reading). STATUS: PASS.
- [ ] **D4. The apnea ML model is presented honestly** — it underperforms (AUROC ~0.23 per-epoch; per-night retrain in progress); demo leans on the rule-based tier and says so. STATUS: PASS as long as the pitch states it.
